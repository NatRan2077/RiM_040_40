**Причины, по которым Акрос не подключался**

Другой сервис. У Акроса сервис ABF0 (запись в ABF1, уведомления из ABF2), а пульт искал только FFE0.
Тип записи. ABF1 поддерживает только запись без ответа, а клиент требовал обычную запись. Поиск сервиса обрывался с ошибкой.
MTU. Акрос сам не запрашивает большой MTU. Соединение оставалось на MTU 23, то есть 20 байт данных, а кадры длиннее.
Режим пейринга. Акрос принимает только LE Secure Connections, а пульт умел только Legacy. Акрос рвал связь (0x13).
Подписка на уведомления. Она включалась до пейринга, и Акрос её не принимал.
Изменения по файлам

src\app_profile\app_rdtsc.c

Добавлены UUID Акроса (ABF0/ABF1/ABF2). Для записи требуется свойство Write Without Response.
Тип счётчика определяется по найденному сервису (РиМ или Акрос).
Для Акроса после поиска сервиса запрашивается MTU 247.
Для Акроса собираются HDLC-кадры, пришедшие несколькими уведомлениями (по полю длины). Есть защита от переполнения bleBuffRx.
Для РиМ добавлена только проверка длины перед копированием, в остальном приём как раньше.
После пейринга подписка на уведомления включается заново.
Параметр AKROS_BLE_PAIRING (1) включает пейринг с Акросом.

**Изменения** 

inc\app_profile\app_rdtsc.h

Типы счётчиков RDTSC_PEER_UNKNOWN / RIM / AKROS.
Функции app_rdtsc_peer_type(), app_rdtsc_pairing_needed(), app_rdtsc_reset_peer(), app_rdtsc_enable_ntf().

src\app_ble.c

Пейринг запускается только после того, как стал известен тип счётчика (ожидание до ~2 с).
Для Акроса в запрос пейринга добавляется флаг Secure Connections. PIN тот же, из SystemInfo.pinCode.
После пейринга с Акросом пульт не переключается на Coded PHY и остаётся на LE 1M.
Исправлено: событие пейринга обрабатывалось в двух местах, теперь оба идут через общую проверку.
При отключении тип счётчика сбрасывается.

...\rdts\rdtsc\api\rdts_client.h

В rdtsc_db_cfg добавлены поля для основного сервиса (РиМ) и запасного (Акрос).

...\rdts\rdtsc\src\rdts_client_task.c

Если сервис FFE0 не найден, пульт ищет ABF0.
При каждом новом подключении сбрасываются хэндлы и счётчики от прошлого соединения. Раньше они оставались, это был баг.

...\hp_library\sec\hp_sec.c / hp_sec.h

Функция hp_sec_set_bond_auth_extra() добавляет флаги к запросу пейринга.
В лог выводятся параметры пейринга и причина ошибки (reason).

...\hp_library\ble\hp_ble_task.c

Стек разрешает оба режима, Legacy и Secure Connections. Secure Connections включается только по флагу, то есть только для Акроса.

Порядок подключения к Акросу

Сканирование → подключение → поиск FFE0, затем ABF0 → MTU 247 → пейринг Secure Connections с PIN → подписка на ABF2 → обмен данными.
